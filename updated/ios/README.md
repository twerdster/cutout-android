# Updated iOS runner

This UIKit application loads an image, accepts foreground/background strokes and calls the shared restored C++ implementation in [`../native`](../native/). Density estimation (FIGTree or histogram), distance propagation (pixel grid or level-set tree), alpha refinement and a 400/800/full-input working limit are independent controls. Seed rasterization, ordered seed correction, the interface, Objective-C++ boundary and run-artifact writer are new work; the preserved historical Android application remains under [`../../source/original`](../../source/original/).

## Build for a device

The recorded build uses Xcode 16.1 with its iPhoneOS SDK and OpenCV 4.12.0's iOS framework. Other toolchain versions have not been tested. The app declares iOS 16.0 as its minimum. The pinned [official OpenCV release](https://github.com/opencv/opencv/releases/tag/4.12.0) archive `opencv-4.12.0-ios-framework.zip` has SHA-256 `86b42c9f141cd9169b91be2fc380b0e556a88a95c98ccc8e7aef8349ab74cf70`. Its ARM64 slice is for iPhoneOS; it does not provide an ARM64 simulator slice. An ARM64 simulator needs a separately built compatible framework.

Set `OPENCV_IOS_FRAMEWORK_DIR` to the directory containing `opencv2.framework`. Signing identifiers are supplied locally; the checked-in project contains no team or device identifiers:

```sh
cd updated/ios
xcodebuild -project CutOutUpdated.xcodeproj -target CutOutUpdated \
  -sdk iphoneos -arch arm64 -configuration Debug SYMROOT="$PWD/build" \
  OPENCV_IOS_FRAMEWORK_DIR=/path/to/framework-parent \
  CODE_SIGNING_ALLOWED=NO build
```

For a signed development build, omit `CODE_SIGNING_ALLOWED=NO` and supply your authorized `DEVELOPMENT_TEAM` and `CUTOUT_BUNDLE_IDENTIFIER` as build-setting overrides. The default bundle identifier is `org.example.cutout.updated`. Automatic provisioning may require `-allowProvisioningUpdates`. Install and launch through Xcode or `devicectl` after trusting the developer/device as required. For example, from `updated/ios`, using your chosen device and signed bundle identifier. Get the device identifier with `xcrun devicectl list devices` and replace the placeholders below:

```sh
xcrun devicectl device install app --device DEVICE_ID build/Debug-iphoneos/CutOutUpdated.app
xcrun devicectl device process launch --device DEVICE_ID YOUR_BUNDLE_ID
```

The checked-in project is generated by `python3 generate_project.py` using only Python's standard library. It references the shared native sources instead of copying or editing them. Native operators compile as C++17; the recovered ANN/FIGTree sources retain a C++14 compilation setting. The project preserves bundled PNG bytes by disabling Xcode's PNG optimizer.

## Use and saved runs

**Examples** loads the procedural ellipse or the bundled CC0 coffee photograph with new demonstration strokes. **Open image** uses Apple's limited photo picker and decodes only the selected image, normalizing orientation, compositing source transparency over white and limiting its longest side to 800 pixels. The displayed image and saved `input.png` use this opaque normalization; the native boundary also initializes its image conversion against white. It requests no broad photo-library access, camera or network permission. Draw green foreground and red background strokes, then select **Segment**. Later strokes erase overlapping opposite-class seeds. Leaving and re-entering the displayed image starts a separate stroke segment.

Changing inputs or options invalidates the current preview and export. The controls are disabled during the single-worker native operation and throughout a controlled batch. Missing seeds and other solver input errors are shown in the status. **Share PNG** opens the standard share sheet for the current saved transparent cutout; it sends nothing automatically. Saving directly to the camera roll is excluded; the app requests no Photos write permission. **Examples → Credits and terms** distinguishes the recovered implementation from its method references and the new port, and links the packaged license texts.

Each successful segmentation automatically saves the normalized input and outputs in the app’s Documents folder. Imported inputs are re-rendered copies of at most 800 pixels on the longest side, not the original files. Saved runs follow normal app-backup settings and accumulate without automatic pruning; this interface has no run-history/delete screen. Use Xcode’s application-container tools to manage exported run folders.

Each successful save creates a new `Documents/runs/<scenario>-<unique suffix>/` directory containing `input.png`, `foreground.png`, `background.png`, `mask.png`, `cutout.png`, `scribbles.json` and a `result.json` completion marker written last. `Documents/last-run.json` normally points to the most recently completed directory. If that optional pointer cannot be updated, the completed run and export remain available and the app reports a persistence warning. A failed image/record save can leave an incomplete new directory; it does not overwrite an earlier completed run or discard the computed preview. Accept a directory only when its completion marker is present.

The mask and seed PNGs contain opaque grayscale values of 0 or 255 in RGBA storage. The mask is binary; the cutout may contain fractional alpha when refinement is selected. The record includes the actual linked OpenCV version, operator choices, dimensions, selected pixels and an elapsed interval covering image/stroke conversion, the native call and output UIImage creation. PNG persistence is excluded. These individual timings do not establish general device performance.

## Controlled fixture runs

The app parses its own documented launch arguments, including a literal `--` separator passed through by device tooling, without changing persistent or global device settings:

```text
-run_fixture YES -example coffee -figtree YES -level_set YES -refine_alpha YES -max_dimension 400
```

For the controlled batch, restart only this app with the launch flag:

```sh
xcrun devicectl device process launch --device DEVICE_ID --terminate-existing YOUR_BUNDLE_ID -- -run_batch YES
```

This requests 14 serial fixture calls: eight ellipse density/distance/alpha combinations, four FIGTree coffee calls at the 400-pixel working limit and two full-resolution refined-alpha coffee calls. Before the first batch case, the app invalidates any prior batch index and writes a new `batch_id` with zero completed runs. `Documents/batch-results.json` records each completed result and reports `batch_complete`/`passed` only after the entire batch finishes. Here `passed` means all cases segmented and saved; independent output checks belong to the validation record. The files remain in the application's own container and can be copied with Xcode's container tooling or `devicectl` using the locally selected application/device.

`CutOutUITests` contains tests for actual drawing, missing-seed recovery, working-size changes, stale-result invalidation and credits/license viewing. The runner requires an unlocked development device with UI Automation enabled. Build and run the shared scheme with your local signing settings:

```sh
xcodebuild -project CutOutUpdated.xcodeproj -scheme CutOutUpdated \
  -sdk iphoneos -destination "platform=iOS,id=DEVICE_ID" \
  OPENCV_IOS_FRAMEWORK_DIR=/path/to/framework-parent \
  DEVELOPMENT_TEAM=YOUR_TEAM CUTOUT_BUNDLE_IDENTIFIER=YOUR_BUNDLE_ID \
  SYMROOT="$PWD/build" -allowProvisioningUpdates \
  -parallel-testing-enabled NO test
```

The [recorded attempt](VALIDATION.json) built the runner but stopped at automation initialization before any test case started; these tests have no completed device result. The picker-presentation test is opt-in by setting `CUTOUT_TEST_PHOTO_PICKER=YES` in the test runner’s environment, because the system picker can display personal photos; it never selects one automatically. Keep device screenshots and raw run logs private until inspected.

The bundled coffee photograph is by Rachel Michetti, courtesy of Pikolo Espresso Bar via scikit-image, under CC0; its unchanged bytes and new stroke provenance are in [`../validation/fixtures`](../validation/fixtures/). It has no independent reference segmentation. Source/build inspection or an app launch alone must not be described as successful segmentation. Runtime evidence belongs in [VALIDATION.json](VALIDATION.json); the declared deployment target is not itself evidence of a minimum-version device test.
